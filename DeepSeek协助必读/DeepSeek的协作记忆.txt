## 长期有效的约定与环境事项

- 环境坑（照做即可）：`五子奇境` 目录属主是 `BUILTIN\Administrators`（父目录与 `.git` 均为 Asus），git 报 dubious ownership。因 git 读仓库本地配置在属主校验**之后**，`safe.directory` 写 `.git/config` **无效**，已写入全局 `C:\Users\Asus\.gitconfig`。系统 PATH 无 git，只能用 GitHub Desktop 自带 git；本机 `HOME` 未设置，需显式 `$env:HOME = "C:\Users\Asus"` 才读得到全局配置（身份已配在其中）。
- 技术栈：纯静态 HTML + CSS + JS，无构建、无第三方库、无 ES Module，双击 `index.html` 即运行。未配置 remote（只做本地提交）。
- 架构总纲：普通 `<script src>` 按序加载，各文件 IIFE 挂 `window.Gomoku`。`cells` 只存 `0|1|2`，**场地状态一律走 `state.arenaState`**。落子流程为顺序调用，无事件总线、无插件系统。`advanceTurn(state)` 是场地事件的唯一挂载点。HUD 手数用 `Board.countStones(state)` 统计（胜负已分时不走 advanceTurn，用 moveCount 会少算制胜那一手）。
- 当前 script 顺序（9 个）：`types → board → arena → river → rules → mode → render/board → render/arena → main`。
- 当前渲染流程（5 步，写在 `main.js` 的 `render()`）：`drawScene`(洞穴背景) → `drawBoard` → `drawArena`(场地，棋子之下) → `drawPieces` → `drawArenaOverlay`(冰块/水波/水位条，**棋子之上**)。冰块必须压在棋子上方，故有 overlay 这一层。
- 校验惯例：每次改动都用 Node 临时脚本（跑完即删）在模拟 DOM 里端到端验证，并回归前几个里程碑。**所有视觉效果均未在真实浏览器确认过，一律待用户人工验收。**

## 2026-10-03 第三次协作：雪山洞穴场地（冰锥 + 冰块）

- 新增 `src/core/arena.js`（场地**规则**，只管数据）：`settleTurns` 严格按「冰锥落下 → 冰块融化 → 补充预警」结算。**未把规则塞进 `render/arena.js`**，也没动 `core/rules.js` 的五连判定。
- 落子合法性新增 `Board.isLegal(board, arenaState, x, y)`：冰块格不可落子，预警格可落子。`Board.place` 刻意**不**查冰块，以保持棋盘数据与场地解耦。
- 踩到的坑（重要）：`settleTurns` 里冰锥先落下生成冰块（=2），紧接着的融化会把它扣成 1，**导致「持续 2 回合」实际只持续 1 回合**。修法：结算前先记下已存在的冰块 key，融化只结算这批，新冰当回合不扣。连带结论：冰块峰值上限是 `2 × 5 = 10`（两波共存），不是 5。
- 视觉：洞穴岩壁 + 飘雪 + 冰川质感棋盘；预警为向下蓝三角（有子时挪到右上角以免被棋子盖住）；冰块为半透明圆角矩形 + 剩余回合小点。
- 校验：Node 临时脚本 111 项（跑完即删），含 20000 次统计验证落下概率 30.00%。

## 2026-10-03 第四次协作：开始界面与模式选择

- 新增 `src/core/mode.js`：`Gomoku.Modes` 一张表 + `Modes.get(id)` 容错回退。**未做插件系统/注册表/动态加载**。
- `index.html` 改为两块 `<div class="screen">`：`#menu` 与 `#game`，用 **HTML `hidden` 属性 + CSS `.screen[hidden]{display:none}`** 切换。启动即停在菜单，不再自动开局。
- `main.js` 顶层加 `appState = { screen, mode }`，配套 `isPlaying()` / `enterMode(id)` / `backToMenu()`；原 `restart()` 更名 `restartGame()`（`G.Main.restart` 保留旧名）。**模式决定场地**：按 `mode.arena` 建立对应 `arenaState`，classic 为 `null`。
- 渲染守卫：`render()`、`scheduleRender()`、`resizeCanvas()`、`ghostFromHover()`、`onKeyDown()` 全部在非 game 屏幕下提前返回。理由：菜单里画布是 `hidden`，`getBoundingClientRect()` 会全 0 导致尺寸/命中算错，且 `rAF` 动画不该在菜单里空转。
- 顺手做的（规格未要求，可改）：经典模式自动隐藏场地图例与说明文字；`Esc` 返回菜单、`R` 重开。菜单底色按规格 `#1A1A2E`。
- 校验：Node 临时脚本 92 项（跑完即删）。

## 2026-10-03 第六次协作：山谷溪流场地（水位 + 冲走）

- 新增 `src/core/river.js`（场地**规则**，只管数据），与 `core/arena.js`（雪山）平级；`core/rules.js` 与 `core/board.js` 的五连逻辑未动。script 顺序在 `arena.js` 后插入 `river.js`。菜单加第三种模式，`Modes.river = { name:'山谷溪流', arena:'river' }`。
- 河流为纵向列：初始 `[6,7]`，水位 ≥30 加 `[5,8]`，≥60 加 `[4,9]`；**扩展永久不缩回**（`updateWater` 只并入不裁剪）。冲走概率 = `waterLevel × 位置系数 / 100`，系数河心 1.0 / 次外圈 0.7 / 最外圈 0.4。
- **水位公式的坑（重要）**：`waterLevel = min(80, max(0,(moveCount-7)*2))` 里的 `moveCount` 必须用**自增后**的值，否则第 8 回合算出来是 0 而不是 2。因此 river 的 `advanceTurn` 把 `moveCount++` 提到结算**之前**（与雪山的顺序不同）。实测关键节点：8→2、22→30、37→60、47→80。
- 结算顺序：`moveCount++ → 水位 → 河流扩展 → 冲走 → 切换玩家`。扩展先于冲走，故新扩进来的列当回合就有风险（已测）。
- 渲染：`drawArena` 现按场地类型分派（有 `riverColumns` 画河道/危险度/雨丝，有 `spikes` 画冰锥，`arenaState` 为 null 什么都不画）。水位条画在棋盘下方 margin 里，**不挤压棋盘**。新增 `notifyWashed` → 水波动画，与 `notifyDrops` 并列。
- 顺带修的真 bug：`types.js` 里 `waterLevelAt` / `riverFactorOf` 误用了不存在的模块级变量名（应为 `Types.xxx`），会在**首次调用时就抛 ReferenceError**；另给 `board.js` 加了 `removeStone` 供两个场地复用。
- 校验：Node 临时脚本 124 项（48 项溪流规则 + 76 项端到端/回归，跑完即删），含 20000 次统计验证三档概率实测 0.40/0.28/0.16。

## 2026-10-03 第七次协作：修河流纵向截断 + 两处几何初始化

- 需求：河流上下比棋盘短，看着别扭。原因：河道原先按 `clipBoard` 裁到**网格矩形**（首行到末行），而棋盘面是整块 640×640，于是上下各露出约 34px 的浅色留白。
- 修法：河道纵向改为铺满整个棋盘面（`y=0, h=geom.size`），并在首尾各叠一段**与棋盘面色对齐的纵向淡出渐变**，避免出现生硬的横向截断。顺带把雨丝、危险度渐变、水流线都改成同一纵向范围。
- 连带发现两处**真 bug**（原色值不一致 + 初始化缺失）：
  1. `render/arena.js` 里 `COLORS.boardBottom` 是 `#c2dcef`，而 `render/board.js` 用的是 `#bcd8ec`——两份棋盘配色不同步，淡出渐变会露出接缝。已统一（淡出必须用棋盘真实面色）。
  2. `render/board.js` 与 `render/arena.js` 的 `configure()` 都**没设 `geom.cell`**，它只在 `gridSizeOf()` 里赋值、即只在首次绘制时才被算出来。因此「configure 之后、首次绘制之前」若询问坐标，`pointToPixel` / `pixelToPoint` / `geometry().cell` 全部返回 0——命中判定会失效。已让两处 `configure()` 都按默认路数先算一次格距。
- 校验：Node 临时脚本 2 套共 59 项（30 项几何/回归 + 29 项全里程碑回归，跑完即删），含「两处棋盘面色一致」「场地与棋盘格心坐标一致」这类跨文件一致性断言。
