## 长期有效的约定与环境事项

- 环境坑（照做即可）：`五子奇境` 目录属主是 `BUILTIN\Administrators`（父目录与 `.git` 均为 Asus），git 报 dubious ownership。因 git 读仓库本地配置在属主校验**之后**，`safe.directory` 写 `.git/config` **无效**，已写入全局 `C:\Users\Asus\.gitconfig`。系统 PATH 无 git，只能用 GitHub Desktop 自带 git；本机 `HOME` 未设置，需显式 `$env:HOME = "C:\Users\Asus"` 才读得到全局配置（身份已配在其中）。
- 技术栈：纯静态 HTML + CSS + JS，无构建、无第三方库、无 ES Module，双击 `index.html` 即运行。未配置 remote（只做本地提交）。
- 架构总纲：普通 `<script src>` 按序加载，各文件 IIFE 挂 `window.Gomoku`。`cells` 只存 `0|1|2`，**所有场地状态一律走 `state.arenaState`**。无事件总线、无插件系统。`advanceTurn(state)` 是场地事件的唯一挂载点。HUD 手数用 `Board.countStones(state)` 统计（胜负已分时不走 advanceTurn，用 moveCount 会少算制胜那一手）。
- 场地模块一律「**规则与渲染分离**」：`src/core/X.js` 只管数据与结算，`src/render/*.js` 只管画。`core/rules.js`（五连判定）始终不动。
- 当前 script 顺序（13 个）：`types → board → arena → river → mine → rules → mode → art → theme → scene → render/board → render/arena → main`。渲染层四个文件的职责：`art.js` 公共绘制工具（纯函数 / 几何口径 / 离屏贴图工厂）、`theme.js` **每个模式的场景与材质主题（纯数据表）**、`scene.js` 场景背景与氛围层、`board.js` 石板与棋子、`arena.js` 场地覆盖物。加载顺序必须是 art → theme → scene/board/arena。
- **一个模式一套主题**（`render/theme.js`）：`classic=星空冰原 / snow=洞穴 / river=山谷 / mine=矿洞`，各自带 `scene`（天幕、岩壁、粒子天气、光柱、边缘层、暗角）+ `slab`（石板上下两色与 RGB、格线、颗粒强度）+ `stone`（棋子下缘反光）+ `ambient`。`Theme.idOf(state, modeId)` 优先用显式 modeId，缺省按 `arenaState` 形状推断（四模式在数据上互斥）。`main.js` 的 `render()` 会把 `appState.mode` 显式传给 `drawScene/drawBoard/drawPieces/drawAtmosphere`。
- 当前渲染流程（7 步，写在 `main.js` 的 `render()`）：`Scene.drawScene`(场景背景，石板之下) → `Board.drawBoard`(石板+格线+星位) → `Arena.drawArena`(场地，棋子之下) → `Board.drawPieces`(棋子) → `Arena.drawMinePreview`(雷区悬停范围) → `Arena.drawArenaOverlay`(冰块/水波/水位条/雷区数字，**棋子之上**) → `Scene.drawAtmosphere`(光柱/边缘霜尘雾/前景粒子/暗角/胜利聚焦，最上层)。冰块与数字必须压在棋子上方，故有 overlay 这一层。
- 棋盘几何：`main.js` 的 `MARGIN_RATIO=0.085`（夹 18..56）给出「石板外留白」＝可见的场景边框；「石板矩形」由 `Art.boardRectOf` 统一给出（网格外沿再多半格），各层共用同一口径。**色值只有一份**：石板上下两色与 RGB 都在主题表里，河流淡出直接引用当前主题，别再各写一份（历史坑：两处色值不一致会露接缝）。
- 渲染循环：对局中由 rAF **连续**驱动（帧末自续），退回菜单后 `isPlaying()` 为假、循环自然停住；reduce-motion 时不连续重绘。因此**任何每帧写 DOM 的代码都必须节流**（见 `main.js` 的 `hudCache`）。石板贴图、场景边缘层、棋子渐变都做了缓存（键含主题 id），**都别在每帧里新建**；贴图缓存只保留当前主题一份（切模式重建一次，换内存）。
- 模式框架：`core/mode.js` 是**一张表** `Gomoku.Modes`（`classic.arena=null`、`snow/river/mine.arena='snow'|'river'|'mine'`）+ `Modes.get(id)` 容错回退。`index.html` 用两块 `<div class="screen">`（`#menu`/`#game`）+ HTML `hidden` 属性切换（**必须**有 `[hidden]{display:none!important}` 兜底，否则 `display:flex` 会把它盖掉）；`main.js` 顶层 `appState = { screen, mode }`，配套 `isPlaying()`/`enterMode()`/`backToMenu()`。**未做插件系统/注册表/路由**。
- 屏幕守卫：`render()`、`scheduleRender()`、`resizeCanvas()`、`ghostFromHover()`、`onKeyDown()` 在非 game 屏幕下提前返回。原因：菜单里画布是 `hidden`，`getBoundingClientRect()` 会全 0 导致尺寸/命中算错，且 `rAF` 动画不该空转。
- 每回合结算顺序**各模式不同**，务必照各自的规格：snow = 场地结算→`moveCount++`→换手；river / mine = `moveCount++`→场地结算→换手（后两者依赖自增后的 moveCount）。成五一律优先，立即判胜且**不进入** `advanceTurn`。
- 校验惯例：每次改动都用 Node 临时脚本（跑完即删）在模拟 DOM 里端到端验证，并回归前几个里程碑。**本次起还能真看画面**：无头 Chrome 截图（`--headless=new --virtual-time-budget=2500 --screenshot=...`，需放宽沙箱）+ 临时 `_crop.js` 裁剪放大；注意无头下 rAF 实测只跑 3 帧、时钟仅推进 33ms，截图里的雪花/水波是**冻结帧**，属正常现象。所有视觉效果仍需用户人工验收。

## 2026-10-03 第十次协作：每个模式一套场景与材质（拆出 theme/scene）—— 已完工

- 起因：四个模式的棋盘背景全是雪山洞穴。根因是场景与石板材质是写死的常量，`drawScene` 无条件画洞穴——第 8 次只是把洞穴「露出来」了，才让这个老问题显形。
- 结构：新增 `render/theme.js`（纯数据主题表）与 `render/scene.js`（场景背景 + 氛围层），`render/arena.js` 只留场地覆盖物（1900 → 约 900 行），`render/board.js` 的石板/格线/星位/棋子反光改为读主题。script 由 11 个变 13 个。
- 四套主题：经典=星空冰原（星点+远山雪脊+中性冰面）、雪山=洞穴（原样保留）、溪流=山谷（崖壁+雾带+雨+湿石板）、雷区=暖色矿洞（岩牙+矿脉自发光+矿灯+尘埃火星+砂岩石板）。
- 坑（重要）：石板/场景/边缘贴图的缓存键**必须含主题 id**，否则切模式会拿到上一个主题的贴图；缓存只保留当前主题一份（4 主题 × 2 张贴图在 DPR=2 下约 52MB，不能全留）。
- 坑：河流淡出的两端色值改为读 `Theme.get(...).slab.topRgb/bottomRgb`——主题一旦换材质，淡出必须跟着换，否则露接缝（第 7 次同类坑的根治）。
- 坑：棋子下缘反光/顶部反光弧也跟着主题走，所以棋子渐变缓存的键也加了主题 id；`drawStone` 里改透明度的写法必须是**相乘**（`ctx.globalAlpha * ...`），否则落子弹入的淡入会被覆盖。
- 校验：Node 端到端 **167 项全过**（新增主题表完整性、四模式主题解析、切模式重建贴图、稳定帧不重建四项），绘制参数零违规；另用无头 Chrome 逐模式截图核对（截图见 `预览/`）。
