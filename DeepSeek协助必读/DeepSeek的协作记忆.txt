## 2026-10-03 第二次协作：五子棋原型 `ice-gomoku/`

- 交付：`ice-gomoku/` 下 7 个文件（`index.html` + `src/core/{types,board,rules}.js` + `src/render/{board,arena}.js` + `src/main.js`）。普通 `<script src>` 按序加载，IIFE 挂 `window.Gomoku`，无构建、无第三方库、无 ES Module。
- 分层：`drawBoard → drawArena → drawPieces` 三层顺序固定，写在 `main.js` 的 `render()` 里；`drawArena` 为空实现但每帧都被调用，`render/arena.js` 已备好 `clipBoard`/`boardRect` 供接入冰锥、溪流、雷区。
- 关键约定：`cells` 只存 `0|1|2`，场地状态走 `state.arenaState`（当前恒为 `null`）；`advanceTurn(state)` 是独立函数，是场地事件（冰锥掉落、水位上涨、雷区倒计时）的唯一挂载点；落子流程为顺序调用，无事件总线。
- 注意点：`advanceTurn` 才递增 `moveCount`，而胜负已分时不再调用它，故 HUD 手数改用 `Board.countStones(state)` 统计，避免少算制胜那一手。
- 校验：已用 Node 临时脚本（3 套共 89 项，跑完即删）覆盖四方向五连、长连取五、断点不误判、点击容差、胜后拒绝落子、重开、HUD 与渲染调用顺序。**尚未在真实浏览器里跑过**，视觉效果待人工确认。

## 2026-10-03 第三次协作：雪山洞穴场地（冰锥 + 冰块）

- 新增 `src/core/arena.js`（场地**规则**，只管数据）：`create` 建 `arenaState` 并补满 5 个预警；`settleTurns` 严格按「冰锥落下 → 冰块融化 → 补充预警」结算。**未把规则塞进 `render/arena.js`**，也没动 `core/rules.js` 的五连判定。
- `index.html` 的 script 顺序变为：`types → board → arena → rules → render/board → render/arena → main`（新增 `core/arena.js`）。
- 渲染由 3 层变 5 步：`drawScene`(洞穴背景) → `drawBoard` → `drawArena`(冰锥) → `drawPieces` → `drawArenaOverlay`(冰块)。**冰块必须画在棋子之后**才对，故拆出 overlay 一层。
- 落子合法性新增 `Board.isLegal(board, arenaState, x, y)`：冰块格不可落子，预警格可落子。`Board.place` 刻意**不**查冰块，以保持棋盘数据与场地解耦；预警不阻止落子。
- 踩到的坑（重要）：`settleTurns` 里冰锥先落下生成冰块（=2），紧接着的融化会把它扣成 1，**导致「持续 2 回合」实际只持续 1 回合**。修法：结算前先记下已存在的冰块 key，融化只结算这批，新冰当回合不扣。连带结论：冰块峰值上限是 `2 × 5 = 10`（两波共存），不是 5。
- 视觉已做：洞穴岩壁 + 飘雪 + 冰川质感棋盘（`render/board.js` 配色同步）；预警为向下蓝三角（有子时挪到右上角以免被棋子盖住）；冰块为半透明圆角矩形 + 剩余回合小点；冰锥落下有 200ms 闪光与冰块弹入。**雪花/闪光依赖 `rAF` 时间戳驱动 `RenderArena.tick()`**。
- 校验：Node 临时脚本 2 套共 111 项（跑完即删）。含 20000 次统计验证落下概率 30.00%、3000 回合长跑验证预警恒为 5 且状态自洽、冰块恰好持续 2 回合、成五不进结算、冰块格拒绝落子、500 回合后 `cells` 仍只含 `0|1|2`。**仍未在真实浏览器确认视觉效果**。

## 2026-10-03 第四次协作：开始界面与模式选择

- 新增 `src/core/mode.js`：`Gomoku.Modes` 一张表两个模式（`classic.arena = null`、`snow.arena = 'snow'`）+ `Modes.get(id)` 容错回退。**未做插件系统/注册表/动态加载**。script 顺序在 `rules.js` 后插入 `mode.js`。
- `index.html` 改为两块 `<div class="screen">`：`#menu` 与 `#game`，用 **HTML `hidden` 属性 + CSS `.screen[hidden]{display:none}`** 切换（未用 JS 改 style，也未做过渡动画）。启动即停在菜单，不再自动开局。
- `main.js` 顶层加 `appState = { screen:'menu'|'game', mode:'classic'|'snow' }`，配套 `isPlaying()` / `enterMode(id)` / `backToMenu()`；原 `restart()` 更名 `restartGame()`（`G.Main.restart` 仍保留该名以免破坏既有调用）。**模式决定场地**：`mode.arena === 'snow'` 才建 `arenaState`，否则为 `null`。
- 渲染守卫：`render()`、`scheduleRender()`、`resizeCanvas()`、`ghostFromHover()`、`onKeyDown()` 全部在非 game 屏幕下提前返回。理由：菜单里画布是 `hidden`，`getBoundingClientRect()` 会全 0 导致尺寸/命中算错，且 `rAF` 动画（雪花）不该在菜单里空转。
- 顺手做的（规格未要求，可改）：经典模式自动隐藏冰锥图例与场地说明文字；`Esc` 键返回菜单、`R` 键重开。
- 菜单底色按规格用 `#1A1A2E`（叠一层冷光与游戏界面同源）。
- 校验：Node 临时脚本 2 套共 92 项（80 项菜单/模式 + 12 项前两里程碑回归，跑完即删），覆盖 12 条验收标准：启动停在菜单、两种模式进入后 `arenaState` 分别为 `null`/正常、切模式棋盘干净、重开保留模式、返回菜单清盘、菜单下 `render` 不排队 rAF、两种模式各 300 回合后 `cells` 仍只含 `0|1|2`。**视觉仍待你在真实浏览器确认**。
